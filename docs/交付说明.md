## 三、已知局限与未完成项（**诚实清单**）

> 完整版（含影响分析与未修原因）见 [开发文档 §19](Wayfare-开发文档.md#十九已知局限与扩展方向)。
> 这里只列**答辩/面试最可能被追问**的部分。**主动讲比被问出来好，且「发现了但权衡后没改」本身就是工程判断力。**

### 3.1 已实现但效果有折扣（4 条最要紧）

| # | 事实 | 正确口径 |
|---|---|---|
| 1 | **「客户端断开即中断 LLM 流」只有 1/3 成立** —— 9 次实测只有 3 次真正掐断，另 6 次模型把整篇生成完并照常落库 | 价值在**「不落半成品数据」**，不在省成本 |
| 2 | 日志里「节省约 N tokens」**高估约 14 倍**（取的是整篇均值，没减已产出；自报 429 / 实际净省约 30） | 引用前必须自己减一次；本项目对外的口径是**「价值在数据完整，不在省钱」** |
| 3 | **`meta.tokens` / `meta.estCost` 不可信**（按「用户 + 时间窗」查日志，被相邻行程污染；已精确对账 8 次中 5 次对不上） | 取数改用 `ai_generation_log` 按 `trip_id` 聚合，或 `/admin/generation/trips/{tripId}/breakdown` |
| 4 | **流式骨架 71.0 s / 全文 87.7 s**，达不到手册目标的「骨架 ~15 s」 | **架构上做不到**：骨架要等 PARSE + CANDIDATE + COMPOSE 三次非流式调用。如实写进 `docs/metrics.md` 第四项 |

### 3.2 未实现（**不要当成"降级效果"**）

| # | 事项 | 说明 |
|---|---|---|
| 1 | **前端地图可视化** | 未接入百度地图 JS API。`VITE_BAIDU_MAP_AK` 只用于判断「能不能渲染」，`mapEl` 没有被任何初始化代码使用 → **有坐标时也不会画点连线**。无坐标（估算模式）时给的是明确占位文案，而不是空白地图 |
| 2 | **接口级限流** | 无实现。成本防护靠「上限 + 熔断 + 客户端断开中断」三件事 |
| 3 | **`admin_operation_log` 写入** | 只有实体与 Mapper，**没有写入代码**；管理员敏感操作不会被记录 |
| 4 | **容器化部署（P8-B）** | 用户明确要求暂缓；仓库内无 `Dockerfile`。目标方案见开发文档 §18 |
| 5 | 举报模块 / 第三方登录 | 表已建（`report` / `user_third_account`），**无 Service / Controller** |
| 6 | 协同过滤推荐 | 只做标签匹配 |
| 7 | 多目的地串行行程 | 一次只支持一个目的地 |
| 8 | 行程导出为图片 / PDF | 未做 |

### 3.3 已发现未修的缺陷（`docs/已知缺陷与修复.md` 之外的新增项）

| # | 缺陷 | 影响 | 修法成本 |
|---|---|---|---|
| 1 | **POI 空结果被缓存 24 h**（`disableCachingNullValues()` 只挡 `null`、不挡空 `List`） | 用户搜一个百度查不到的词，24 h 内再搜仍返回空 | **一行**：`@Cacheable` 加 `unless = "#result == null || #result.isEmpty()"` —— 待拍板 |
| 2 | `mode` / `provider` 分不出「实测」与「缓存命中」 | 判冷热只能靠 `external_call_log` 行数增量（冷 +1 / 热 +0） | 需要改缓存层语义 |
| 3 | 触发重排的**具体规则码**没进日志（只有 `VALIDATE` 一条 `success=0`） | 无法统计「哪条规则最常导致重排」 | 中等 |
| 4 | 现网 `sys_config` 缺 `llm.breaker.*` / `llm.price.qwen-*` 键 | 走代码默认值（大模型熔断阈值仍是 3），但**后台改不到** | 手工 INSERT 即可，见 [部署说明 §5.5](部署说明.md#55-后台配置改不动--不生效) |
| 5 | `GovernedExternalHttpClientTest` **会真实外呼**（真实域名 + 假 AK，实测 429 重试占 6.8 s） | 假 AK 大概率被拒不计配额，但**未验证** | 建议改 MockWebServer |
| 6 | `qwen3.8-flash` 已不可用（476 s/次、失败率 55%、输出 token 是别家 13~16 倍） | 保留在降级链末尾但不宜启用 | 换模型即可 |

### 3.4 客观环境局限

1. **县域 POI 覆盖不足**：实测 `寿阳+古建筑` 返回 0 条、`大同+古建筑` 返回 14 条 —— **做演示要挑城市**。
2. **百度 `tag` 参数填错不报错、只静默返回城市级垃圾**（比报错危险）→ 本项目只用 `query`。
3. **门票与评分是缺失字段**：地图接口常不返回，页面显示"未知"，**不伪造**。
4. **估算模式误差未标定**：地图关闭时距离为模糊估算，无实测误差范围（靠强制模糊表述缓解）。
5. **百度地点检索免费额度 100 次/天、并发 3 QPS**（`status=401` 是并发超限，不是额度用完）。

## 六、一致性校验结论（P8-A 交付的一部分）

> 六项检查**逐条真跑过**，下面是结论与原始口径。凡口径需要限定的，都写明了限定条件 ——
> 不做「跑一条 grep 就宣布通过」这种糊弄。

### 6.1 检查 4 需要特别说明：`grep photoshare` 不是「全仓为 0」

手册写的检查项是 `grep -r "photoshare\|photo-share" .` 结果为空。**逐字执行并不为空**，原因是
三类文件**必然**包含旧名，且都是有意保留的：

| 类别 | 文件 | 为什么保留 |
|---|---|---|
| 有意留档 | `docs/refs/application.yml-摄影平台版.yml`、`docs/refs/技术文档-学习版.md` | 旧项目的参考原件（P0-A 明确搬过来留档，用于对照） |
| 迁移脚本本身 | `scripts/Init-Wayfare.ps1` | 它的职责就是「把旧名替换成新名」，必然含旧名 |
| 描述纪律的文档 | `README.md`、`docs/Wayfare-开发文档.md`、`docs/Wayfare-重构提示词.md`、`docs/Wayfare-文件迁移清单.md`、`docs/交接文档.md`、`docs/交付说明.md` | 它们**引用**这条纪律或记录迁移决策表；把手册里的那行也 grep 掉是自相矛盾的 |

所以正确口径是两条，都可复现：

```bash
# 口径 A —— 运行时代码与配置，必须为 0（这是真正要保证的）
grep -rn "photoshare\|photo-share" \
  wayfare-backend/src wayfare-frontend/src db \
  wayfare-backend/pom.xml wayfare-frontend/package.json wayfare-frontend/vite.config.js \
  wayfare-backend/.env.properties.example
# → 无输出 ✅

# 口径 B —— 全仓命中文件清单（逐个说明，见上表）
grep -rln "photoshare\|photo-share" . | grep -v '^./.workbuddy/' \
  | grep -v '^./wayfare-backend/target/' | grep -v '^./wayfare-frontend/node_modules/' | sort
# → 9 个文件，全部是上表三类之一
```

**结论：口径 A 通过（运行时代码零残留）；口径 B 的 9 个命中全部属于「有意留档 / 迁移脚本 / 纪律描述」，
没有一处是真实命名残留。** 这条口径修正已同步写进 [开发文档 附录 A](Wayfare-开发文档.md#附录-a命名规范)。
