### 技术栈锁定（不许升级、不许换同类库）

- 后端：JDK 17 / Spring Boot 3.3.5 / MyBatis-Plus 3.5.7 / MySQL 8.0 / Redis 7 / Maven
- 鉴权：自建 `JwtInterceptor` + jjwt 0.12.6，**不要引 Spring Security**
- 前端：Vue 3.4 + Vite 5 + Element Plus 2.6 + Pinia + Axios，**JS 不用 TypeScript**
- 禁止引入：**WebFlux**（与 Spring MVC 冲突）、新 ORM、新状态管理库
- 大模型支持三家：**Qwen（阿里云百炼，主力）**、**GLM（智谱）**、**DeepSeek**
  （2026-09-20 经用户批准由「两家」扩为三家；原因：GLM 的免费模型要么推理弱、
  要么单次 70 秒装不进超时，而 qwen3.8-flash 实测 9~14 秒且能把「周末」算对。
  接入成本很低 —— `LlmProviderFactory` 按 `provider.name()` 自动注册，只加了一个类。
  ⚠️ 百炼的模型名**大小写敏感**，必须全小写 `qwen3.8-flash`，写成 `qwen3.8-Flash` 会报 `model_not_found`）

### 三条铁律

1. **事实数据永不来自大模型。** 坐标 / 距离 / 时长只能来自地图 API，或显式标记 `ESTIMATED`。大模型只做语义决策（分天、配时长、写讲解）。
2. **连接器可插拔，任一时刻系统完整可用。** 地图整体关闭后，系统走估算模式继续全功能运行 —— 是**能力降级**，不是功能降级。
3. **画像注入是增强，不是必需。** 用户关掉隐私开关后规划照常跑。

### 4.3 沙箱工具的三个坑（会让你以为程序坏了）

| 坑 | 表现 | 对策 |
|---|---|---|
| **Bash 工具全废** | `ls` / `head` / `dirname` 全部 `command not found`，管道直接 exit 127 | 列文件用 **Glob**，搜内容用 **Grep**，跑命令用 **PowerShell** |
| **PowerShell 的 stdout 常常丢** | 只回 `Command completed with exit code 0`，明明有输出却看不见 | 把结果写文件再 Read。**写文件要用** `[IO.File]::WriteAllText($p,$t,(New-Object Text.UTF8Encoding($false)))`（无 BOM）—— `Out-File -Encoding utf8` 会带 BOM，Read 会当二进制拒绝显示 |
| **写 `.ps1` 必须 UTF-8 带 BOM** | 无 BOM 时 PowerShell 5.1 按 ANSI 解码，脚本里中文全成乱码（**不报错**，只是输出难看、替换失配） | 写完补一步：`$t=[IO.File]::ReadAllText($p,(New-Object Text.UTF8Encoding($false))); [IO.File]::WriteAllText($p,$t,(New-Object Text.UTF8Encoding($true)))`。**注意 `.bat` 的要求正好相反：必须无 BOM** |

> 附：写迁移/批处理脚本时的通用护栏（只读源目录、目标非空即停、先 `-DryRun`、
> `-Force` 用改名备份代替删除、拒绝把目标设为源目录父级）已沉淀在本机技能
> `win-local-service-verify` 里，可直接复用。

### 5.1 解决 Redis（唯一硬阻塞）

三选一，装好就行（无密码、6379、db 0）：

```powershell
# 方案 A：有 Docker 的话（最省事）
docker run -d --name wayfare-redis -p 6379:6379 redis:7-alpine

# 方案 B：Windows 原生（无 Docker）
#   下载 tporadowski/redis 的 Windows 版 或 Memurai，解压后
```

所以：**做 P0-A / P0-B 时可以暂时不管，但最晚必须在 P0-C 之前装好**，别等到那时候才发现。

## 7. 已经探明的坑（别重踩）

### 7.1 旧代码里两个"假实现"（P0 阶段必须修掉）

| 问题 | 证据 | 要求 |
|---|---|---|
| **多图发布是假的** | 旧 `WorkServiceImpl` 把 `imageUrls` 写死为 `Collections.singletonList(coverUrl)`；`work_image` 表在但无实体/Mapper | P0-C：先 insert work 拿 id，再**批量 insert work_image**（sort 从 0 递增），cover_url 取第一张。`getById` 要从 `work_image` 按 sort 正序查真实列表 |
| **分类是硬编码的** | 旧 `WorkPublish.vue` 硬编码 8 个分类，后端无 Category 实体/Mapper/Controller | P0-B/P0-C：建 `category` 实体与服务；P0-D：前端改为**从 `/categories/tree` 拉取** |

> 这两条答辩现场容易被抓，务必在 P0 阶段真正做掉。

### 7.2 双厂商接入的两个必踩细节

- **GLM（智谱）**：`https://open.bigmodel.cn/api/paas/v4`，模型 `glm-4-flash`（便宜，调试用）。
  用 `response_format: {"type":"json_object"}` 时，**prompt 里必须出现 "json" 字样**，否则不生效。
  遇到 400 提示不支持 `response_format` → 自动降级为纯 prompt 约束重试一次。
- **DeepSeek**：`https://api.deepseek.com/v1`，模型 `deepseek-chat`。
  若用 `deepseek-reasoner`，返回里会多一个 `reasoning_content`，**必须忽略**，否则思维链会混进攻略文案。
  流式要拿到 token 统计需在请求体加 `stream_options: {"include_usage": true}`。

两者都走 OpenAI 兼容协议 → 公共逻辑放 `AbstractOpenAiCompatibleProvider`，子类只写差异。

### 7.4 工程纪律

- **依赖纪律**：新增依赖必须先说明用途与版本，确认后再写进 `pom.xml` / `package.json`
- **别跑错目录**：`npm` 只在前端目录、`mvn` 只在后端目录。后端出现 `package.json` /
  `package-lock.json` / `node_modules` 就是跑错了（本项目已经发生过一次，见 §5.3）
- **命名纪律**：验收时 `grep -r "photoshare\|photo-share" .` 必须为空
- **事实纪律**：接口路径、字段名、方法名必须来自真实存在的代码或依赖；不确定就说「需要查文档」，**不要编造**
- **SSE 与 JWT 冲突**：前端**不能用 EventSource**（它不能自定义请求头，带不了 JWT），
  必须用 `fetch` + `ReadableStream` 手动解析事件块
- **资料写入纪律**：文档里不得出现代码里不存在的能力
