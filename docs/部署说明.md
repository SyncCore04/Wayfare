# Wayfare · 部署说明

> 适用版本：`HEAD = 299535c`（2026-09-24）｜ 对应开发文档：[`Wayfare-开发文档.md`](Wayfare-开发文档.md)
> 本文覆盖**本机 / 单机部署**（开发与答辩演示用）。
> ⚠️ **容器化部署（Docker）尚未实施** —— 用户明确要求暂缓，仓库里没有 `Dockerfile` / `docker-compose.yml`。
> 目标方案与「实施前必须补的三件事」见 [开发文档 §18](Wayfare-开发文档.md#十八部署)。

## 一、环境要求

| 组件 | 版本要求 | 说明 |
|---|---|---|
| JDK | **17** | `pom.xml` 锁 `<java.version>17</java.version>`；不要用 21/8 |
| Maven | **3.9+** | 需要能访问 Maven 中央仓库或阿里云镜像 |
| Node.js | **18+** | Vite 5 要求 `^18.0.0 \|\| >=20.0.0`，**Node 16 会直接起不来** |
| MySQL | **8.0** | 字符集必须是 `utf8mb4` |
| Redis | **7**（6+ 亦可） | 无密码、默认 db 0 即可 |
| 浏览器 | 现代浏览器 | SSE 需要 `fetch` + `ReadableStream` |

端口占用：后端 **8080**（context-path `/api`），前端 **5173**。

## 二、部署步骤

### 2.1 建库（两份脚本，都会自动 `CREATE DATABASE IF NOT EXISTS wayfare`）

```bash
cd Wayfare
mysql -u root -p < db/schema.sql        # 内容域与用户域 14 张表
mysql -u root -p < db/schema-trip.sql   # 行程域与治理域 8 张表 + sys_config 初始值
```

建完应当是 **22 张表**，可用下面的语句自查：

```sql
SELECT COUNT(*) FROM information_schema.tables WHERE table_schema = 'wayfare';
-- 期望 22
```

> 🔴 **`db/schema-trip.sql` 对本项目的表是 `DROP TABLE` 后重建。**
> **已经在跑的系统不要重复执行它** —— 会把 `sys_config` 里后台改过的厂商 / AK / 单价、
> 以及 `trip` / `trip_item` 全部清空。只有**首次建库**才执行。
>
> 🔴 如果你已经跑过一段时间，并想补上 `llm.breaker.*` 这几个后加的配置键，
> **不要重跑整脚本**，手工 INSERT 即可（见 [§5.5](#55-后台配置改不动--不生效)）。

### 2.2 启动 Redis

Redis 7 任意方式皆可，只要 `localhost:6379` 无密码可连：

```bash
redis-server                              # 本地安装
# 或
docker run -d --name wayfare-redis --restart unless-stopped -p 6379:6379 redis:7-alpine
```

自查：`redis-cli ping` 应返回 `PONG`。

> **Redis 挂了会怎样**：`sys:config` 读不到会回落 L1（yml）配置；熔断计数失效则退化为「每次都试」；
> JWT 黑名单失效会导致「登出后旧 token 仍可用」。**不要在生产里省掉 Redis。**

### 2.3 配置后端密钥

```bash
cd wayfare-backend
cp .env.properties.example .env.properties
```

编辑 `.env.properties`：

| 变量 | 必填 | 留空的后果 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | ✅ | 数据库连不上，启动直接失败 |
| `QWEN_API_KEY` | ⬜ | 该厂商视为未配置，降级链自动跳过 |
| `GLM_API_KEY` | ⬜ | 同上 |
| `DEEPSEEK_API_KEY` | ⬜ | 同上 |
| `BAIDU_MAP_AK` | ⬜ | 地图能力整体不可用，全流程走估算（`ESTIMATED`） |
| `JWT_SECRET` | ⬜ | 用 yml 里的开发默认值 —— **生产必须覆盖** |

> ✅ **三个大模型 Key 全空 + 地图 AK 空 = 系统仍然完整可用。**
> 会自动回落内置离线 Mock（内容由模板生成），全链路含前端流式渲染照常演示。
> 见 [§4 如何关闭地图、如何用 mock 模式](#四如何关闭地图如何用-mock-模式)。
>
> 也可以用**系统环境变量**代替该文件 —— `application.yml` 里写的是 `${GLM_API_KEY:}` 这类占位符，
> 两种来源都能解析到，任选其一（同名前缀，同名时环境变量优先）。
>
> ⚠️ `.env.properties` 已在 `.gitignore` 里，**不要把它提交进仓库**。

### 2.4 启动后端

```bash
cd wayfare-backend
mvn spring-boot:run
```

成功标志（日志末尾）：

```
====================================================
  Wayfare 后端启动成功
  接口文档: http://localhost:8080/api/swagger-ui/index.html
  健康检查: http://localhost:8080/api/health
====================================================
```

自查：

```bash
curl --noproxy '*' http://localhost:8080/api/health
# {"status":"UP",...}
```

> 💡 `--noproxy '*'` 不是多余的：本机若配了 HTTP 代理，`curl localhost` 会走代理返回 502，
> 看起来像「后端没启动」。

### 2.5 启动前端

```bash
cd ../wayfare-frontend
npm install
npm run dev
# → http://localhost:5173
```

Vite 已代理 `/api` 与 `/uploads` 到后端，无需额外配置 CORS。

生产构建：`npm run build`，产物在 `dist/`；用任意静态服务器托管，
需自行把 `/api` 反代到后端 8080、把 `/uploads` 指向上传目录。

### 2.6 登录与首次配置

| 账号 | 密码 | 角色 |
|---|---|---|
| `admin` | `Admin123456` | 管理员（可进 `/admin/connectors` 与 `/admin/generation`） |

> 这是**演示凭据**，写在 README 与本文里有意的（答辩要能直接登录看后台），**不是泄漏**。
> **正式部署请立刻改密码**，并不要把真实密码写进任何文档。

首次登录后台后按顺序做三件事（`/admin/connectors`）：

1. 填 Key / AK → 点各厂商的**连通性测试**（会真实外呼，注意配额）
2. 按需**一键开启地图**（默认关闭）
3. 填**单价**（`llm.price.*`）—— 不填则成本显示「未配置」，这是有意设计

## 三、三个 Key 的申请与配置

### 3.1 阿里云百炼 Qwen（`QWEN_API_KEY`）

1. 打开 <https://bailian.console.aliyun.com>，登录阿里云账号
2. 开通「百炼」服务 → 进入 **API-KEY** 页面 → 创建 API Key
3. 把 Key 填进 `.env.properties` 的 `QWEN_API_KEY`
4. 模型名在 `application.yml` 的 `llm.providers.qwen.model`，当前 `qwen3.8-flash`

> 🔴 **模型 id 大小写敏感，必须全小写**。写成 `qwen3.8-Flash` 会报 `model_not_found`，
> 报错文案看起来像「没有权限」，其实是名字不对。
> 🔴 该端点还聚合了 `glm-5.3` / `deepseek-v4-flash` / `kimi` 等模型，换模型只改这一行。

### 3.2 智谱 GLM（`GLM_API_KEY`）

1. 打开 <https://open.bigmodel.cn>，注册并实名
2. 「API Keys」页面创建密钥
3. 填进 `GLM_API_KEY`
4. 模型名 `application.yml` → `llm.providers.glm.model`，当前 `glm-5.3-flash`

> 🔴 **`glm-5.3` 系列强制思考、不允许关闭**，`application.yml` 里已配 `reasoning-effort: low`。
> 合法值只有 `low` / `high` / `max`（传 `none` / `minimal` / `medium` 会被 400 拒绝，code 1210）。
> **不传这个字段时它按默认高档跑**，实测「60 秒产出 3556 字思考、正文 0 字」——
> 非流式下就是「超时且无任何返回」，看起来像服务挂了。
> 若坚持要改，**改完必须实测一次 CANDIDATE 阶段**（那是长输出最容易撞超时的环节）。

### 3.3 DeepSeek（`DEEPSEEK_API_KEY`）

1. 打开 <https://platform.deepseek.com>，注册并充值
2. 「API Keys」创建密钥
3. 填进 `DEEPSEEK_API_KEY`
4. 模型名 `application.yml` → `llm.providers.deepseek.model`，当前 `deepseek-flash`

> 🔴 **`deepseek-chat` 已不在官方模型列表**（列表里只有 `deepseek-flash` 与 `deepseek-v4-pro`），
> 配旧模型名会失败。
> 🔴 `deepseek-flash` **是推理模型**，官方声明 `effort.default_level = high`，必须显式下发
> `reasoning_effort`（已配 `none`）。参数名**必须**写 `reasoning_effort` ——
> 写成 `effort` 会被**静默忽略**，然后按默认 high 跑。
> 同一 prompt 实测：`none` 0.8 s / 96 tok ｜ `low` 5.5 s / 1171 ｜ `high` 9.7 s / 2139，
> 而解析质量四档全对。合法 8 档：`none` / `minimal` / `low` / `medium` / `high` / `xhigh` / `ultra` / `max`。
> ⚠️ **峰谷计价**：工作日 9:00–12:00、14:00–18:00 价格翻倍（单价按空闲时段填，高峰成本上限约翻倍）。

### 3.4 百度地图 Web 服务 AK（`BAIDU_MAP_AK`）

1. 打开 <https://lbsyun.baidu.com>，登录百度账号
2. 控制台 → 「应用管理 → 我的应用」→ 创建应用
3. **应用类型必须选「服务端」**（选「浏览器端」得到的 AK 调 Web 服务 API 会被拒）
4. 把 AK 填进 `BAIDU_MAP_AK`（或后台连接器管理页的 `map.baidu.ak`，后者优先）

**配额与限制（免费个人认证）**：

| 项 | 值 |
|---|---|
| 地点检索 | **100 次 / 天** |
| 并发 | **3 QPS**（`status=401` 是并发超限，**不是日额度用完**） |
| 路线规划 | 有独立额度 |

> 🔴 **AK 填错时百度返回 `status=200`**（不是 4xx），靠 message 文案兜底识别 —— 所以「接口返回 200」
> 绝不等于「Key 是对的」。诊断接口会把这类情况归到 `MAP_AUTH_FAIL`。
> 🔴 **`tag` 参数填错不报错、只静默返回城市级垃圾**（实测 `tag=风景名胜` 时结果从真实 POI 变成
> 「广州市/邵阳市」）—— **这比报错危险得多**，所以本项目只用 `query`，不要给它加 `tag`。
> 🔴 **`region` 传县级名可能返回 0 条**（实测 `寿阳+古建筑` = 0 条、`大同+古建筑` = 14 条）。
> **做演示要挑城市**，不要挑县。
> ⚠️ 项目内有「请求间隔 + 早停 + 检索词收敛」保护，一轮完整验收约 9 次调用。

**前端 JS API AK（可选，`VITE_BAIDU_MAP_AK`）**：在 `wayfare-frontend/.env.local` 里配置
（该文件**不在仓库里**，也不在 `.env.properties` 里）。
> ⚠️ 注意：**项目目前并未接入百度地图 JS API 本体** —— 这个变量只被 `TripResult.vue` 用来判断
> 「能不能渲染地图」。配了它也不会画出点位与连线。这是**未实现项**，见
> [开发文档 §19](Wayfare-开发文档.md#十九已知局限与扩展方向)。若要做前端地图可视化，需要另行开发。

## 四、如何关闭地图、如何用 mock 模式

### 4.1 关闭地图（能力降级，不是功能降级）

有两种方式，都不需要重启：

| 方式 | 操作 |
|---|---|
| 后台页面 | `/admin/connectors` → 地图总开关关掉 |
| 接口 | `POST /api/admin/config/map/enabled`（管理员） |

关闭后：

- `mapMode` 变为 `ESTIMATED`，`trip_item.distance_meters` / `duration_seconds` **保持 NULL**
- 界面上来源角标从绿（实测）变成橙（估算），**不显示空白地图**，而是给明确占位文案
- **零外部调用，不消耗任何地图额度**
- `ROUTE` 阶段发的是 `FALLBACK` 状态（**不是 `error`**）—— 这就是「能力降级」的协议层证据

想拿到可复核的证据，跑演练脚本（需要后端已启动）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\drill-fallback.ps1
# 只做降级对比、不注入故障：
powershell -ExecutionPolicy Bypass -File scripts\drill-fallback.ps1 -SkipFaultInjection
```

20 条断言全绿并自动产出 `docs/drill-report.md`。
⚠️ **脚本的阶段 B 会真实调用百度地图（约 6 次地点检索）**，会消耗日配额；
脚本会自动记录并恢复演练前的 `map.enabled` 与 AK。

### 4.2 无任何 Key 的 mock 模式（零成本演示）

**什么都不用配**。三个大模型 Key 全空时，`LlmCapabilityResolver` 会回落 `MockLlmProvider`：

- 意图解析、候选检索、行程编排、攻略文案**全部有输出**（模板化的合法结构）
- SSE 五类事件照常推送，前端流式渲染照常工作
- `meta` 里会标记 `provider=mock`，日志里 `ai_generation_log.provider = mock`

想显式只用 Mock（例如答辩演示不想花钱 / 不想被上游抖动打断）：

```sql
-- 方式一：直接指定
UPDATE sys_config SET config_value = 'mock' WHERE config_key = 'llm.active-provider';
-- 方式二：只留 mock 在降级链里（等价于禁用其它三家）
UPDATE sys_config SET config_value = 'mock' WHERE config_key = 'llm.fallback-order';
```

改完等 **≤30 秒**（`sys:config` 缓存 TTL）或让后台里任意一次配置写入（会立即清缓存）即生效。

或在后台 `/admin/connectors` 把厂商切到 `mock`。

> ⚠️ 切回来时注意：**不要用 `db/schema-trip.sql` 重跑**来「恢复默认」（它会 DROP 整表），
> 把 `active-provider` 改回目标厂商即可。

## 五、常见故障排查表

### 5.1 启动期

| 现象 | 根因 | 处置 |
|---|---|---|
| `Communications link failure` / `Access denied for user 'root'` | `MYSQL_ROOT_PASSWORD` 没填或填错 | 检查 `.env.properties`；确认 MySQL 已启动 |
| `Unknown database 'wayfare'` | 建库脚本没跑 | 按 [§2.1](#21-建库两份脚本都会自动-create-database-if-not-exists-wayfare) 执行两份脚本 |
| `Port 8080 was already in use` | 端口被占（**或本机有 `SERVER__PORT` 类环境变量顶掉了配置**） | `netstat -ano \| findstr :8080` 找占用者；**不要改项目里的端口配置**去绕 |
| `Port 12515 was already in use`（数字很怪） | 宿主/沙箱注入了 **`SERVER__PORT`**（双下划线），Spring 宽松绑定覆盖了 `server.port` | 启动前 `unset SERVER__PORT SERVER_PORT`，或加 `--server.port=8080`（命令行参数优先级最高） |
| `Unsupported class file major version 61` | 用了 JDK 8/11 编译 | 换 JDK 17，确认 `JAVA_HOME` 指向 17 |
| `No plugin found for prefix 'spring-boot'` / 找不到 plexus launcher | MSYS 环境变量干扰（Windows + Git Bash） | `unset MSYS_NO_PATHCONV MSYS2_ARG_CONV_EXCL` |
| 日志里出现 `Tomcat initialized with port XXXX`，XXXX 不是你配的值 | 同 `SERVER__PORT` 那条 | 看这行日志就能确认是不是被覆盖了 |

### 5.2 运行期 · 大模型

| 现象 | 根因 | 处置 |
|---|---|---|
| 某厂商一直 `LLM_AUTH_FAIL` | Key 无效/过期，或模型名不对 | 后台 `/admin/connectors` 看诊断卡片的失败原因四分类（没配 Key / 网络不通 / 认证失败 / 限流） |
| `model_not_found`，文案像没权限 | **模型 id 大小写不对**（百炼全小写） | 改成 `qwen3.8-flash` 全小写 |
| 请求跑满超时、什么都拿不到 | **推理模型没下发思考强度**（GLM 5.3 / DeepSeek 都是推理模型） | 确认 `application.yml` 里 `reasoning-effort`（GLM）/ `reasoning_effort`（DeepSeek）已配；DeepSeek 这个名字写错会被**静默忽略** |
| 阶段超时，但换一家就正常 | 长输出（CANDIDATE / COMPOSE）真的需要 90 秒以上 | 确认 `llm.timeout-ms` ≥ 240000；它是 L2 键，**改完不重启即生效** |
| 连续失败后整批生成都失败 | **熔断已打开**（大模型默认 3 次失败即跳闸），期间所有请求直接跳过该厂商 | 等 300 秒半开，或**调高 `llm.breaker.fail-threshold`**；批量跑真实生成前建议先清 `cb:fail:*` |
| 成本显示「未配置」而不是数字 | 单价是 0（= 未配置），或该行 `provider=map`（地图无单价） | 填 `llm.price.{vendor}-input` / `-output`，**用字符串存小数**（用 INT 会把 0.3 取整成 0） |
| `COMPOSE` 崩溃 / 返回 `LLM_PARSE_FAIL` | `max-tokens` 太小，长 JSON 被截断（`finish_reason=length`） | 确认 `max-tokens` 给足（qwen 4096 / glm 16384 / deepseek 32768） |

### 5.3 运行期 · 地图

| 现象 | 根因 | 处置 |
|---|---|---|
| 接口返回 200 但结果为空、或报 `MAP_AUTH_FAIL` | **AK 有误时百度也返回 `status=200`** | 用 `GET /api/connector/map/search` 看原始返回；重新申请**服务端**类型的 AK |
| 报 401 | 并发超 3 QPS，**不是日额度用完** | 降并发/加间隔；项目已有请求间隔与早停 |
| 结果全是城市级噪声 | 用了 `tag` 参数（填错不报错） | **只用 `query`** |
| 某个县搜出来 0 条 | `region` 传县级名覆盖不足 | 换城市；或依赖「扩半径 → 放宽标签」的降级路径 |
| 明明调通了，第二次却查不到 | **空结果被缓存了 24 小时**（已知缺陷：`disableCachingNullValues()` 只挡 `null`、不挡空 `List`） | 清掉对应 Redis 键：`redis-cli --scan --pattern 'map:poi:*' \| xargs redis-cli del`（**该缺陷未修**） |
| 熔断一直不恢复 | 打开时长 300 秒 + 半开试探仍失败 | 调好后 `POST /api/connector/map/breaker/reset` 手动复位，不必干等 |
| 关掉地图后行程没有距离 | **这是设计如此**：`ESTIMATED` 模式下数值列必须为 NULL | 见 [§4.1](#41-关闭地图能力降级不是功能降级)；这是铁律一的落地，不是 bug |
| 开了熔断后想验证降级效果，测不出来 | 请求命中了 POI 缓存，根本没走到百度、也就不会失败 | 演练脚本会**先清 Redis 的 POI 缓存**；手工验证时也要先清 |

### 5.4 运行期 · 前端

| 现象 | 根因 | 处置 |
|---|---|---|
| 前端 401 反复跳登录 | token 过期或已登出（黑名单命中） | 重新登录；若 Redis 不可用，黑名单会失效 |
| 规划页一直转圈到最后失败 | 浏览器/axios 默认超时（常见 60s）等不到长生成 | **走 SSE 流式接口**（前端已实现）；`trip.sse-timeout-ms` 默认 10 分钟 |
| 生成了但地图是空的 | **项目未接入百度地图 JS API**（未实现项） | 不是配置问题；无坐标时会显示明确占位文案 |
| 上传图片失败 | 扩展名/MIME 不在白名单，或超过 10 MB | 白名单见 `application.yml` 的 `file.upload.allowed-*` |
| 前端构建报 Node 版本错误 | Node < 18 | 升级到 Node 18+（Vite 5 的硬要求） |

### 5.5 后台配置改不动 / 不生效

| 现象 | 根因 | 处置 |
|---|---|---|
| 改了 `sys_config` 但行为没变 | `sys:config` Redis 缓存 30 秒 | 等 30 秒；或走后台接口写（写后会**立即清缓存**）。⚠️ 用「读一个直查库的接口」是证明不了缓存被清的 |
| **某个键在后台配置页找不到** | 该键在现网库里**不存在**（脚本后加的键，而库是脚本之前建的） | 见 [§5.5](#55-后台配置改不动--不生效) |
| 诊断页显示大模型「阈值 5」但实际第 3 次就跳闸 | 历史缺陷：快照曾写死读 `map.breaker.*`（**已修**） | 现在快照按前缀读各自阈值；若仍不对，检查是否改到了别的环境的库 |

**`llm.breaker.*` / `llm.price.qwen-*` 这几个键在现网库里缺失**（如实记录）：它们是在本机建库
**之后**才补进 `db/schema-trip.sql` 的，而脚本对 `sys_config` 是 `DROP TABLE` 重建，所以现网库里没有。
缺键时走**代码默认值**（大模型熔断阈值仍是 3），但**后台改不到**。需要时手工补：

```sql
INSERT INTO sys_config (config_key, config_value, value_type, group_name, description, updated_by) VALUES
('llm.breaker.fail-threshold','3','INT','llm','连续失败多少次后熔断该厂商',0),
('llm.breaker.open-seconds','300','INT','llm','熔断保持多久（秒）后再放行一次试探',0),
('llm.price.qwen-input','0','STRING','llm','Qwen 输入单价（元/百万token）',0),
('llm.price.qwen-output','0','STRING','llm','Qwen 输出单价（元/百万token）',0);
```

> `config_key` 有唯一索引，重复 INSERT 会报错 —— 先 `SELECT` 确认不存在再插。

### 5.6 数据维护

| 事项 | 说明 |
|---|---|
| 跑 `mvn test` 之前 | **必须先清两张日志表**：`DELETE FROM ai_generation_log; DELETE FROM external_call_log;` —— `AiLogServiceTest` 断言的是**绝对条数**，库里残留数据会让它失败 |
| 删一条行程 | `trip` 表**没有任何外键约束**，必须按序手工清理 `trip_item` → `trip_day` → `trip`，以及 `ai_generation_log` / `external_call_log` 里的关联行，否则会留孤儿行（已实测踩过） |
| 想拿真实的 token / 成本数字 | **不要用 `meta.tokens` / `meta.estCost`**（它们按「用户 + 时间窗」查日志、被相邻行程污染）。用 `ai_generation_log` 按 `trip_id` 聚合，或调 `GET /api/admin/generation/trips/{tripId}/breakdown` |
| 想清 POI 缓存 | `redis-cli --scan --pattern 'map:poi:*' \| xargs redis-cli del`（注意：**裸 TCP 手搓 RESP 协议时长度要用 UTF-8 字节数**，键里有中文时用字符数会算少、命令被静默丢弃） |

## 六、安全提醒（部署前必看）
