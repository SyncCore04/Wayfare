## 四、跨页面的全局行为（P5-D 收尾项）

| 能力 | 实现 | 位置 |
|---|---|---|
| **全局加载条** | 请求拦截器维护计数器，`>0` 时顶部显示 2px 进度条 | `api/request.js` + `App.vue` |
| **统一错误提示** | 全部走 axios 拦截器的 `ElMessage`，页面不再各写一套 | `api/request.js` |
| **错误码翻译** | 把 `LLM_DISABLED` / `LLM_NOT_AVAILABLE` / `LLM_AUTH_FAIL` 等翻成「用户能据以行动」的话 | `Plan.vue` 的 `describeError` |
| **生成中途离开确认** | 路由守卫（站内跳转）+ `beforeunload`（刷新/关页）双保险 | `Plan.vue` |
| **图片懒加载** | `<img loading="lazy">` | `WorkCard.vue` |
| **长列表控制单次渲染量** | 时间轴用**分天 tabs**，一次只渲染一天 | `TripTimeline.vue` |
| **移动端导航** | 768px 以下隐藏桌面导航，收进汉堡抽屉菜单 | `DefaultLayout.vue` |
| **移动端步骤条** | `el-steps` 的 `direction` 是 prop，**只能用 JS 切**（媒体查询改不动） | `Plan.vue` |

## 五、界面上的「数据诚信」可视化（本项目的差异化点）

这几处是答辩时最值得讲的：**用户能一眼看出哪些数据是可信的**。

| 位置 | 表现 |
|---|---|
| 行程条目右侧 | 来源角标：**绿「实测」** / 灰「缓存」 / 橙「估算」 / 蓝「手动」 |
| 结果页与详情页顶部 | 地图可信度三色条：绿=实测 / 蓝=缓存 / 橙=估算 |
| 攻略卡片右上角 | **「AI 生成」角标** —— 区分人工原创与 AI 辅助生成 |
| 详情页行程区块 | 「由 `qwen3.8-flash` 生成 · 约束校验重排 1 轮」 |
| 生成过程中 | 阶段降级时显示橙色 `FALLBACK`：「地图不可用，已切换为估算模式」 |
| 费用汇总 | 只汇总有数据的项，并明确写「住宿与交通没有数据，未计入」 |

## 六、需人工目视的条目（Agent 自证不了）

1. **375px 宽度下全部页面可用**（验收 1）—— 代码里有媒体查询，但「可用」要眼睛看
2. **生成中途关闭页面弹出确认**（验收 2）—— 需要真实跑一次生成才能触发
3. **首页卡片与详情页行程区块的实际观感**（含 AI 角标位置、时间轴排版）
4. **发布页的跳转与预填**（`/plan` → 「发布为攻略」→ `/publish?tripId=xx`）
5. **汉堡菜单在真机上的手感**
